### 5. Make your first Kaggle submission, before further training

```powershell
python infer.py --manifest manifest.csv --ckpt runs/base/seed0/best.pt --model smp --encoder resnet34 --out submission_baseline.csv --split-seed 0 --tta 0 --skip-tune --skip-validation
python submission_check.py --csv submission_baseline.csv --manifest manifest.csv --sample 5
```

Submit the output file through https://www.kaggle.com/competitions/filament-segmentation-2026/submit.

The CSV must have exactly two columns: `filament_id,segmentation_rle`. Each row describes one predicted filament with a unique ID such as `20160920230134Lh_1`. The second column contains compressed COCO RLE counts, not start-length pairs. The competition uses 2048 x 2048 masks. Images with no predictions have no placeholder row.

The `.metadata.json` file beside the CSV records the checkpoint, selected post-processing configuration, number of images, count of predicted filaments and measured end-to-end prediction time. Keep it as experimental evidence.

### 6. Tune post-processing after the first accepted submission

```powershell
python infer.py --manifest manifest.csv --ckpt runs/base/seed0/best.pt --model smp --encoder resnet34 --out submission_base_tuned.csv --split-seed 0 --tta 0 --tune-samples 4
python submission_check.py --csv submission_base_tuned.csv --manifest manifest.csv --sample 5
```

This searches several threshold, closing and small-object-filter settings on four reproducibly selected validation entries, evaluates the chosen setting on the full validation split, and then generates test predictions. **This is much more computationally expensive than `--skip-tune --skip-validation`.** A four-image tuning sample is a speed compromise, not strong evidence of the optimal parameter values.

Only upload the tuned file if it validates and appears preferable. Record the tuning subset size and local PQ. Do not use the Kaggle test score as your only basis for selecting hyperparameters.

### 7. Train the clDice enhancement with seed 0

```powershell
python train.py --manifest manifest.csv --out runs/cl --model smp --encoder resnet34 --pretrained 1 --epochs 40 --bs 4 --crop 512 --lr 0.0003 --val-every 5 --cldice 0.5 --workers 0 --seed 0 --split-seed 0
```

The added clDice loss encourages better overlap along thin connected filament structures. It may be substantially more memory intensive than BCE plus Dice on a 4 GB RTX 3050.

If you get CUDA out-of-memory, try `--bs 2` or `--crop 256`. For a strictly controlled loss comparison, the baseline must use the same changed batch and crop settings. Otherwise describe the result as a combined configuration comparison, not an isolated clDice effect.

### 8. Run seeds 1 and 2 for the baseline

```powershell
python train.py --manifest manifest.csv --out runs/base --model smp --encoder resnet34 --pretrained 1 --epochs 40 --bs 4 --crop 512 --lr 0.0003 --val-every 5 --workers 0 --seed 1 2 --split-seed 0
```

This creates `runs/base/seed1/` and `runs/base/seed2/`, preserving `runs/base/seed0/`. Three seeds give a mean and standard deviation across independent model initializations and training randomness. Keep `--split-seed 0` fixed for fair comparison. Run three seeds of the enhanced model as well if compute time permits.

### 9. Test compression using laptop-safe settings

```powershell
python compress.py --manifest manifest.csv --ckpt runs/base/seed0/best.pt --model smp --encoder resnet34 --finetune 2 --bs 1 --crop 256 --workers 0 --val-limit 24 --split-seed 0 --out compression_results.csv
```

The default `--val-limit 24` evaluates a reproducible subset of 24 validation annotation entries so the experiment is manageable. It is **not** directly comparable to the earlier full-validation PQ of 0.3168. The compression table compares all its variants using the same 24-entry subset. Use `--val-limit 0` for the full validation split if you have time.

Unstructured pruning zeroes weights but does not necessarily reduce dense model storage or inference time. FP16 can reduce model memory, but always measure output quality and actual speed.

## Troubleshooting

**Repeated seed 0 training:** use `--seed 1 2`. Existing checkpoints are protected against accidental overwrite in the revised training script.

**CUDA out of memory:** use smaller batches first, then smaller crops. For clDice try batch size 2 or 1. Quit any other GPU-intensive software.

**`model.safetensors` download:** the first use of a pretrained ResNet34 encoder may download its ImageNet weights. The checkpoint-loading inference command sets encoder weights to `None`, so it does not need to re-download encoder weights.

**Missing JSON:** confirm that the `--root` directory contains `train/` and `test/`, and `train/` contains the annotation JSON.

**Kaggle paths:** Kaggle input data is read-only. Generate `manifest.csv`, masks, training logs and predictions under `/kaggle/working`. Use the path-discovery commands in `KAGGLE_SETUP.md`.

**Local PQ differs from Kaggle:** compare against the organizer's self-evaluation notebook at https://www.kaggle.com/code/azimahmadzadeh/self-evaluation-notebook. The local implementation uses standard IoU > 0.5 one-to-one matching, while the competition may implement additional checks. A local score is not a guaranteed leaderboard score.

**Kaggle rejection:** read the actual Kaggle error message, verify the two-column CSV, unique IDs, compressed COCO counts, and that the file covers the test set predictions. The local checker cannot guarantee Kaggle acceptance.
